# Qt 3D Scanner: object capture

The Qt scanner builds a TSDF surface from calibrated Kinect depth. Kinect v2 RGB is projected onto that surface and exported as **vertex color** in PLY or OBJ. It does not create a UV texture image. The mesh preview updates during capture; stop to inspect the final mesh and export it.

## Choose a capture setup

- **Move Kinect · object stays still:** Put the object on a stable support. Keep the object and background stationary while moving the sensor slowly around it. Translation, pitch, roll, and yaw are all estimated. Start with the object centered and nearer than the background. The scanner locks to the nearest substantial depth cluster in the center and keeps a 1 m deep band in room coordinates as the sensor moves. Registered RGB detail helps recover sideways motion of flat surfaces; depth ICP refines the pose. Fast camera movement or a featureless object can still cause tracking loss. The scanner skips low-confidence frames instead of merging them at an arbitrary pose.
- **Rotate object · camera stays still:** Fix the Kinect in place and rotate the object slowly on a turntable. Begin with hands out of view. The scanner uses the same foreground depth band and attempts to remove a detected horizontal support plane. Tracking estimates yaw and in-plane translation. This path does not detect or remove hands; pause or move hands away before capturing each new view.
- **Turn head · camera stays still:** Center the head in the depth view at least 0.65 m from the sensor and keep shoulders still. The scanner uses a head-sized 3D crop instead of the broad object band, excludes the support-plane detector, and uses RGB detail when available to help align the turning head. It constrains accumulated pose drift near the initial head position and fuses only distinct views. Turn slowly enough for consecutive frames to overlap. The crop is fixed near the initial head position, so large leaning motion can leave it. A single frontal sensor cannot measure the hidden back of the head until it becomes visible during the turn.

The object must be roughly 0.35–4 m from the sensor and fit in the central 80% of its depth image. Keep unrelated foreground objects outside that region. The scanner crops by depth and image bounds, so it cannot semantically distinguish a hand from an object at the same distance. For a clean object mesh, use a support or turntable rather than holding the object throughout the scan.

Select the sensor and mode, press **Start TSDF capture**, collect several viewpoints, then press **Stop** and **Export colored mesh**. PLY is the most portable choice for vertex colors. OBJ writes vertex colors as an extension that some viewers do not display. The Studio scanner described in `SCANNER-3D-VIEWPORT.md` is a separate, more advanced pipeline.

Qt tracking remains sequential: it does not yet revisit earlier frames for loop closure or global pose-graph correction. For a full orbit, accumulated drift may still leave a seam. A short, slow pass with enough visible color and depth detail is more reliable than a fast turn. Use **Move Kinect** for a handheld sensor; the turntable mode deliberately restricts motion because it assumes a fixed camera.
